# SEO and accessibility audit: lampcircle.truefrontier.app

Run date: 2026-11-04. Branch: `overflow/lampcirclesiteseo`, off `origin/main` at `99ab6a4`.

## Bottom line

The site was already in good shape. Its head tags, social cards, sitemap, robots file, skip link and reduced-motion handling were all correct. This branch fixes 11 smaller issues in source.

One real problem is left for you, because fixing it changes how the hero looks. The small amber line above the headline ("Live song maps · Free for Mac") crosses a candle flame. Where it does, contrast drops to 2.2:1 on a phone, against 4.5:1 needed. See [Open: needs your call](#open-needs-your-call).

Lighthouse on the branch build gives 100 for Accessibility, SEO and Best Practices, on both mobile and desktop. Lighthouse can't measure text that sits over a photo, so it misses the hero problem.

## Open: needs your call

### 1. Hero eyebrow over the candle flame (WCAG 1.4.3, fails)

The amber caps line is 16px semibold, so it needs 4.5:1. I hid the text, took screenshots, and read the brightest background pixels under each line of text.

| Screen | Eyebrow, worst spot | Headline (sans line) | Paragraph |
|---|---|---|---|
| Phone, 390×844 | **2.20:1** | 4.25:1 (passes; large text needs 3:1) | 9.76:1 |
| Tablet, 768×1024 | **3.73:1** | 7.04:1 | 10.24:1 |
| Desktop, 1280×800 | **2.98:1** | 5.29:1 | 10.00:1 |

Only the eyebrow fails. The rest of its line sits on dark background; the problem is where it crosses a flame.

What I tried: a darker overlay on phones only (top of the gradient at 70% instead of 30%). That reached only 4.28–4.46:1, and the flame turned gray. I didn't commit it.

Options, best first:

1. **Put the eyebrow on a small frosted pill**, in the same style as the navbar glass (for example `rounded-full bg-midnight/70 px-s4 py-s2 backdrop-blur`). This keeps the flame and guarantees contrast.
2. Darken the overlay where the eyebrow sits. This works only if you accept a dimmer flame.
3. Re-crop the photo on phones (`object-position`) so no flame sits behind the text. This depends on the photo, and it needs a check at each screen size.

### 2. Video play button name (axe "label in name", not scored)

The button's name is "Play the Lamp Circle walkthrough, 28 minutes". The visible "28:34" badge isn't part of that name, so axe flags it. Lighthouse doesn't count this audit in its score.

I left it as is. The button's visible label is really the play icon, and "28 minutes" reads better aloud than "28:34". If you want the flag gone, change the name to "Play the Lamp Circle walkthrough, 28:34".

### 3. Smaller notes, no change made

- **No custom 404 page.** Stray URLs get Netlify's default page. A `public/404.html` with a link home would fix that.
- **`/index.html` returns 200** as a copy of `/`. The canonical tag already covers this, so no action is needed.
- **The meta description is 164 characters.** Google may cut the last few words. I left the copy alone.
- **App rich results.** Google shows the app rich result only with real ratings or reviews (`aggregateRating` or `review`). Don't add placeholder ones. Add them only if real reviews exist.
- **Footer column titles** ("The app", "Get it", "Fine print") are `<p>` tags. That's fine, because each footer `nav` has its own label. Make them headings only if you want them in heading navigation.
- **One lint warning** at `src/site.js:8` existed before this work, and I didn't touch it because it's out of scope. `window.fathom?.trackEvent(name)` would clear it with the same behavior.

## Checked and fine

- **Head:** title (53 characters), description, canonical, `og:*` and `twitter:*` tags, `lang="en"`, viewport, `theme-color`.
- **Images and icons:** `og.png` is 1200×630, matching its tags. Icons are 180, 192, 512 and 96 px, matching their declared sizes.
- **Crawling:** `robots.txt` allows everything and points to the sitemap. The sitemap is valid XML with one URL. Both return 200.
- **Transport and headers:** HTTP redirects to HTTPS with a 301. HSTS, `nosniff`, frame and referrer headers are set.
- **Headings:** one h1, then h2 and h3 in order. On the branch: h1 hero, h2 "Tap. Map. Worship." with three h3s, h2 walkthrough, h2 "We focus on the living room.", h2 "Three rules it plays by." with three h3s, h2 "Map one song tonight."
- **Alt text:** both photos have descriptions. The logo mark inside the labeled home link has `alt=""`. The footer logo is "Lamp Circle". The video poster has alt text, and the button around it has its own name.
- **Landmarks:** `header`, `nav` "Main", `main#main`, and a `footer` with two labeled `nav`s.
- **Keyboard:** the skip link is the first Tab stop and shows on focus. Every focusable element has a `:focus-visible` outline, in amber on the dark sections. Tab order follows the page, with no positive `tabindex` and nothing focusable inside `aria-hidden`.
- **Links:** all 7 in-page anchors (`#main`, `#top`, `#features`, `#walkthrough`, `#why`, `#how`, `#download`) resolve. There are no duplicate IDs.
- **Download target:** `Lampcircle_universal.dmg` is an asset on the latest release, v0.1.1 (checked with `gh release view`).
- **Motion:** with reduced motion on, all content shows and nothing loops.
- **Text contrast:** all 170 visible text nodes pass on solid backgrounds after the fixes. Each check composited the text's alpha and its parents' opacity.
- **Live site:** the live HTML matches a local build of `main`.

## How this was checked

- **Local only.** I built the site and served a copy from a scratch folder with the Fathom script removed, so no analytics calls were made. The browser still loaded the page's own public assets: Google Fonts, the Unsplash photos and the Loom poster.
- **Live site, GET only:** `/`, `/robots.txt`, `/sitemap.xml`, `/og.png`, `/site.webmanifest`, the favicons and brand images, `/index.html`, a made-up path to see the 404, and the HTTP-to-HTTPS redirect. Nothing else was sent, and no search engine was pinged.
- **Lighthouse,** run locally through Chrome DevTools, mobile and desktop. Most sections fade in on scroll, so the first run saw only the hero. The later runs used `prefers-reduced-motion: reduce`, which shows every section.
- **My own contrast check** read the computed colors of every visible text node in the page. For text over photos, I read real screenshot pixels with the text hidden, using the 99th-percentile and the brightest pixel under each line.
